# ADR-005: Phase 1 source and benchmark conventions

Status: accepted for synthetic dataset v1 only. Date: 2026-09-14.

Every decision below is an **AuditLens project convention, not an authoritative professional audit standard**. These decisions make a reproducible teaching fixture; they do not resolve real organizational policy.

| Decision | Why needed | Alternatives considered / consequences |
| --- | --- | --- |
| Preserve employees, accounts and vendors as separate entities | Match the Phase 0 ERD and distinguish employment from account access | Flattening employee fields into users or replacing vendors with customers would duplicate/contradict the existing model. Add full_name, department and hired_at to employees for lifecycle context. |
| Employment active/inactive; inactive requires ended_at; account active/disabled independently | Represent retained access and transactions after termination | Full HR/status history is deferred. One hire/end interval, no rehire, suspension or service-account fixture. A disabled current account is not evidence of when it was disabled; TX-005 uses employee ended_at only. |
| One approval stage, all submitted invoices require approval before approved/paid or payment creation; decision rows authoritative | Prevent accidental missing-approval fixtures | Thresholds, delegation and multi-stage authorization deferred. Latest decision by decided_at then id wins; rejection invalidates prior approval. Draft/submitted are not automatically exceptions. Rejected examples become void. No redundant invoice approved_at. |
| Invoice states draft/submitted/approved/paid/void; decisions approved/rejected | Preserve proposed vocabulary | Adding rejected/cancelled invoice states is unnecessary. Fifty void examples have rejection decisions. |
| Positive IDR amounts only; one invoice per payment; partial payments allowed; cumulative confirmed payments define overpayment | Exact monetary QA without FX ambiguity | Refunds, credit notes, reversals, other currencies and allocation tables deferred. Schema deliberately restricts currency to IDR for v1. Money is decimal text; QA sums integer cents with BigInt. |
| External references are not unique; internal UUIDs and master references are unique | Permit genuine business duplicates with structural integrity | Unique invoice reference would prevent the benchmark. Duplicate key is vendor/reference/currency/amount for invoices and invoice/reference/currency/amount for confirmed payments. Trim/uppercase references. Count groups, store all members. |
| Fixed as-of 2026-09-14T10:00Z; Asia/Jakarta weekdays 09:00–17:00, end exclusive; no holidays in synthetic calendar | Define dormancy and unusual-hour negative controls | Host clock/local timezone, real holiday feeds and adjustable clock would break reproducibility. Dormancy is strictly older than 90 days; null login uses account creation. Transactions can use an existing session; last login is not last activity. |
| Fixture policy supplies per-account allowed role codes; admin role grants only administration, not all financial capabilities | Six excess-access fixtures need a baseline | Inferring appropriateness solely from assigned roles is circular. Enterprise job entitlement policy remains Phase 4; the fixture baseline is outside operational tables and is legitimate future test configuration, unlike ground truth. |
| Dot-separated activity vocabulary, redacted before/after values; synthetic change_reference in JSON | Follow original dictionary and preserve review context | Uppercase events, a generic transaction table, source IP and payment method add no required benchmark information. Current role grants reconcile with the event history. |
| sample:// references identify synthetic supporting records; polymorphic log entity IDs remain snapshots without FK | Preserve existing evidence/reference boundary | External URL fetching and live cross-schema evidence FKs rejected. Fixture QA checks current log targets exist. No real attachments or evidence storage delivered. |
| Frozen source output with per-table canonical SHA-256 digests and versioned metadata; fixture generatedAt equals fixed as-of | Reproduce identical benchmark bytes and identify drift | Wall-clock generation timestamp intentionally omitted. Hash is not trusted external integrity. Future repeatable-read extraction and durable evidence snapshots remain Phase 3 decisions. |
| Revised exact fixture counts supersede Phase 0's tentative 30 SoD conflicts / 20 dormant / 15 duplicate-payment groups | Current Phase 1 request specifies broader 14-category benchmark | Keep existing planned audit test IDs. Fixture SOD-001/002 count observed transactions; add planned SOD-003/004 for those procedures. Original SOD-001/002 still describe entitlement conflicts, not the same units. |

The local seed writer uses the existing development administrator, guarded by environment, loopback host and dedicated database name. It is tooling, not an audit reader. No authentication, reader credential, ingestion or detection engine is implemented. Existing source-reader write-denial acceptance remains unresolved until a real PostgreSQL instance and roles are available.
